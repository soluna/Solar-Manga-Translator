# InkStage：交给 Luna Max 的优化提纲

这是方向与执行范围，不是完成或验收记录。先核对当前分支已有改动，避免重复实现；具体实现由 Luna Max 展开，主 agent 负责取舍与验证。

## 新旧取舍

保留新版：首页、页面列表、审校、擦除、术语表和设置的职责更清楚；统一的颜色、字号、控件与主题基础值得继续使用；画布对照和文本框列表适合漫画审校。

继承旧版：围绕整本漫画连续处理的多选、批量样式、字体预览和工作区操作。新版页面拆分后，应特别补上跨页面的任务状态和工作位置，避免每次切换都要重新找上下文。

需要改善：功能与真实数据的衔接不能落后于界面；首页应更突出继续工作；审校页应把空间让给漫画与高频编辑；浅色主题的弱文字、弹出菜单和提示需统一检查。视觉效果尚未完成当前浏览器实测，不能把源码判断记为视觉验收。

## 三批执行

| 批次 | 具体范围 | 验收目标 |
| --- | --- | --- |
| P0：可靠完成一次工作 | 导入、真实页面数据、设置与术语表保存；连续编辑、冲突恢复、撤销重做；任务重连与取消；擦除坐标；页面状态与导出有效性 | 用合成素材完成导入→识别→翻译→修改→重嵌→导出；失败保留编辑，刷新可恢复，旧结果不会冒充新结果 |
| P1：高效处理整本漫画 | 原文修正与 OCR 重试；多选、合并、批量字体/字号/方向；真实字体预览；当前页与待处理页重嵌；人工审校标记、下个问题、返回上次位置；可调侧栏 | 连续处理多页时能批量修改、找到问题、恢复位置；操作范围清楚，画布保持可用 |
| P2：视觉与入口收口 | 首页优先显示继续工作和导入；项目列表提高密度；统一深浅主题、菜单与提示；稳定编号、快捷键说明与焦点 | 常用桌面窗口下主要控件可见，文字可读，键盘可操作；新用户知道下一步做什么 |

P0 未稳定前，不扩大视觉改版。P1 中影响主操作可见性、导致无法继续工作的布局问题，提升到 P0 处理。

## 不要犯的错误

- 不再推翻新版视觉，也不为迁移方便删除旧版的有效工作能力。
- 不自造一套前端业务状态：沿用后端 Page Document、稳定区域 ID 和页面产物版本。
- 不用 Mock 返回成功、按钮变色或构建通过代替真实工作流验收。
- 不把“已保存”“已重新嵌字”“人工已审校”合并成一个完成状态；编辑后应识别过期产物。
- 不让慢请求覆盖新编辑，不在保存失败时清空草稿；OCR 撤销/重做应恢复既有结果，避免重复调用模型。
- 不让“当前页”操作意外处理全书，不因重连重复启动任务。
- 不把浏览器字体预览承诺为最终排版效果，不把在线翻译或修图描述成完全离线。
- 不改动用户项目、原图和输出，不提交密钥，也不覆盖嵌套上游仓库的既有修改。

每批交付只需说明：做了什么、如何验证、剩余缺口。主 agent 核验真实接口和页面表现，再决定是否进入下一批与合并。
